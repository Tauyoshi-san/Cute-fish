# AQUA ALTER — 制作方針と必要事項

## プロダクトの核

「次の一口で何になる？」という期待を中心に、餌を与える、環境を変える、進化を発見する、図鑑を埋める、価値を次の水槽へ投資する、という循環を3〜8分の短いセッションで成立させる。魚は死なず、失敗は遠回りとして扱う。

## アート方向の比較

1. リアル寄り：観賞価値と高級感が最も高い。奇抜な進化には説得力づくりが必要で、アニメーション単価も高い。
2. 中間（推奨）：魚らしい骨格に、絵本的な面・発光・少し大きな目を足す。通常種から幻想種まで連続性があり、全年齢へ展開しやすい。
3. かわいい：収集欲、グッズ化、低年齢層への訴求が強い。長時間眺めるアクアリウムとしての静けさは弱くなりやすい。

推奨する固有表現は「水彩のにじみを持つ半透明のヒレ」「環境由来の模様が体表に育つ」「成魚でも魚らしい小さな目」「深い青緑に珊瑚色と発光色を一点だけ使う」。特定作品の輪郭、配色、UI、名称は参照せず、実在魚の資料と独自の形状ルールから設計する。

## 本制作に必要な決定事項

- 対象プラットフォーム：Web/PWA、iOS、Androidの優先順位
- 対象年齢、主要地域、対応言語、縦画面か横画面か
- 1日の想定プレイ時間、短期・中期・長期の継続目標
- 初期魚種数、進化総数、餌・装飾・水・フィルターの総数
- 進化条件を完全秘匿、ヒント表示、段階開示のどれにするか
- 売却を「販売」「里親へ送り出す」など、世界観上どう表現するか
- 広告事業者、年齢同意、プライバシー、広告頻度、無課金設計
- 課金の有無、価格帯、通貨バランス、分析イベント
- セーブ同期、アカウント、機種変更、オフライン進行の要否
- 音楽、環境音、効果音、通知、アクセシビリティ要件
- 正式タイトル、ロゴ、利用規約、プライバシーポリシー、ストア素材

## コンテンツ制作リスト

- 魚ごとの正面設定画、左右スプライト、待機・旋回・食事・進化・喜び
- 餌、稚魚、装飾、水質、フィルター、汚れ、通貨、希少度のアイコン
- 水槽背景、前景、泡、水面、光芒、パーティクル、昼夜差分
- ショップ、図鑑、個体詳細、設定、チュートリアル、広告導線
- BGM 2〜3曲、水中環境ループ、UI音、食事音、進化ジングル
- 各進化の名前、説明、発見ヒント、条件、販売価値、出現演出

## 技術計画

- Phaser + TypeScript + Vite。Canvas/WebGLは水槽描画、DOMはHUDとメニューを担当
- シミュレーション状態を描画から分離し、将来のサーバー保存や広告SDK差し替えに備える
- 端末内保存から開始し、リリース前にスキーマ移行、クラウド同期、不正対策を追加
- 60fps、初回ロード5MB目標、画像アトラス、WebP/AVIF、音声圧縮、低性能端末モード
- Playwrightによる主要導線、スクリーンショット比較、実機タッチ、復帰・回転・オフライン試験

## マイルストーン

1. 企画検証：1水槽、5進化、3餌、3装飾、経済、図鑑、初回体験
2. アート縦切り：正式魚3体と進化演出、背景、UI、音を最終品質で制作
3. コンテンツα：進化ツリー、ショップ、保存、バランス、分析を実装
4. β：広告SDK、同意、端末QA、チュートリアル、運用ツール、ストア準備
5. リリース：クラッシュ・継続率・広告完了率を監視し、魚と水槽テーマを定期追加

## 初版の受け入れ基準

- 初見で30秒以内に魚を選び、餌を与えられる
- 5分以内に最初の進化か、その明確な予兆を体験できる
- 主要操作がマウスとタップのみで完結する
- 360px幅でも水槽と操作対象が隠れず、文字が読める
- 魚が死ぬ、資産が不可逆に消える、広告を強制される状態がない
- 再読み込み後も進行を保持し、破損データから初期状態へ復旧できる
